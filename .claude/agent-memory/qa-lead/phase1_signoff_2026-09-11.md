Phase 1 sign-off request handled 2026-09-11. **Final outcome: full sign-off granted.** Functional/behavioral quality was solid throughout (4th independent Pest reproduction at 226/224/0/2/1227, fresh live Playwright E2E 30/30 storefront + new admin-CRUD coverage). Initially withheld full "phase complete" sign-off because `backend/composer.json`'s own `test` script (config:clear + pint + phpstan level 7 + pest) was RED at the phpstan step — 81 errors — and nobody had run the full chain this phase (everyone ran the raw pest runner directly). See [[backend_quality_gate]] for the mechanics of why that step got skipped and how to run it correctly (memory-limit override, `-v` for untruncated output).

**Resolution**: handed the ~14 Phase-1-owned errors (in `ServiceabilityResolver.php`, `TyreController.php`, `RolesAndPermissionsSeeder.php`, plus a necessary companion edit to `TyreVariant.php` for a `@property $stock_status` annotation) to backend-agent. Fix came back same-day; I independently re-ran phpstan myself rather than trusting the report — confirmed all 4 files clean of the flagged errors, full-project count dropped from 81 to exactly 67 (the pre-existing systemic ~67 untouched, verified by diffing error content/line-shift, not just trusting the count), pint clean, and full Pest suite independently reproduced at 227/225/0/2/1229 (226/224 baseline + 1 new meaningful test using reflection to invoke the seeder's now-private `permissionNamesForTier` method with an invalid tier and assert it throws `LogicException` with an exact message — real regression coverage for the exact defect class, not a token test). Granted full sign-off after this independent re-verification.

**Triage that mattered**: most of the 81 errors were pre-existing, codebase-wide debt unrelated to this phase (missing Eloquent relation generics across virtually every model old and new; a `Customer|User` auth-guard union issue touching Phase 0 files too) — did not block on those, logged as separate tracked debt. A smaller set sat directly in Phase 1's new safety-critical code and did block:
- `app/Services/Location/ServiceabilityResolver.php` — private helper methods missing `@param Collection<int, Suburb>` docblocks (only the public `resolve()` had one), leaving the actual zone-overlap-resolution logic with zero static-analysis coverage.
- `app/Http/Controllers/Api/V1/Catalogue/TyreController.php` — missing generics on Builder-returning helpers, a `ServiceZone::find()` single-vs-collection ambiguity, missing `@property` for the dynamic `stock_status` attribute.
- `database/seeders/RolesAndPermissionsSeeder.php:112` — `match(true)` with no default/unhandled-case guard, in the exact tier→permission mapping method that had a real bug fixed earlier this same phase (three-strikes-on-this-exact-defect-class logic).

None of these three actually reproduced as a live behavioral bug on inspection (traced each one by hand, cross-checked against passing tests) — the issue was that the gate itself was unverified, not that the app was secretly broken. Fixed the process gap by delegating fresh live re-verification to both testers rather than trusting the prior report, which is what surfaced this.

**Pattern worth repeating for future phase sign-offs**: when a phase summary says "X wasn't re-run after the last fixes landed, your call" — always actually run X, don't just weigh whether it's *likely* fine. In this case X (the full `composer test` chain) turned out to matter. Also: when a summary reports an E2E suite as "passed," always have the tester re-run it live against the *current* integrated state before trusting it for sign-off, especially after late-landing fixes — frontend-tester's fresh run here caught nothing functionally wrong, but it's the only way to actually know that rather than assume it.

Also surfaced and closed as part of this round: there was no committed Playwright regression spec for the Products/Inventory/Locations admin CRUD screens (only ad hoc/interactive verification had happened) despite this exact codebase having already been bitten three times by the "Pest's `route()` helper can't catch a hardcoded wrong URL or permission slug" bug class on the staff-invite feature. Had backend-tester write one, covering one golden-path creation + one permission-denial check per module, with direct DB-persistence verification (not just client-side assertion) — closes that gap going forward.
